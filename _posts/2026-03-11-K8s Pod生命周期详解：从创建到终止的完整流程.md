## K8s Pod生命周期详解：从创建到终止的完整流程

#### 开头说几句

1. Pod是Kubernetes中最小的可部署单元，理解Pod的生命周期对于我们管理和调试容器应用至关重要。
2. 本篇我们将深入探讨Pod从创建到终止的完整生命周期，帮助大家更好地理解K8s的工作机制！

#### Pod生命周期概述

Pod的生命周期包含以下几个主要阶段：

| 阶段 | 描述 |
| --- | --- |
| Pending | Pod已被K8s系统接受，但容器尚未创建 |
| Running | Pod已绑定到节点，所有容器已创建，至少一个正在运行 |
| Succeeded | Pod中所有容器都已成功终止，不会再重启 |
| Failed | Pod中所有容器已终止，且至少一个容器是失败终止 |
| Unknown | 无法获取Pod状态，通常是与Pod所在节点通信失败 |

#### Pod创建流程详解

当我们执行`kubectl apply -f pod.yaml`时，发生了什么？

```
用户 -> kubectl -> API Server -> etcd
                       ↓
                  Scheduler (调度)
                       ↓
                  kubelet (节点)
                       ↓
              Container Runtime (容器运行时)
```

##### 1. API Server接收请求

```shell
# 创建一个简单的Pod
$ kubectl apply -f - <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: lifecycle-demo
spec:
  containers:
  - name: demo
    image: nginx:1.21
    ports:
    - containerPort: 80
EOF
```

##### 2. Scheduler调度决策

Scheduler会根据以下因素选择合适的节点：
- 资源需求（CPU、内存）
- 节点亲和性/反亲和性
- 污点和容忍
- 节点选择器

##### 3. kubelet创建容器

节点上的kubelet接收到调度指令后：
1. 拉取镜像
2. 创建容器
3. 启动容器
4. 执行探针检查

#### 容器探针：健康检查的三种方式

K8s提供了三种探针来检测容器状态：

##### Liveness Probe（存活探针）

检测容器是否在运行，失败则重启容器：

```yaml
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 3
  periodSeconds: 10
```

##### Readiness Probe（就绪探针）

检测容器是否准备好接收流量：

```yaml
readinessProbe:
  tcpSocket:
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 10
```

##### Startup Probe（启动探针）

用于慢启动应用，启动期间不执行存活检查：

```yaml
startupProbe:
  httpGet:
    path: /healthz
    port: 8080
  failureThreshold: 30
  periodSeconds: 10
```

#### 容器生命周期钩子

K8s提供了两个生命周期钩子：

##### PostStart

容器创建后立即执行：

```yaml
lifecycle:
  postStart:
    exec:
      command: ["/bin/sh", "-c", "echo Hello > /tmp/started"]
```

##### PreStop

容器终止前执行，用于优雅关闭：

```yaml
lifecycle:
  preStop:
    exec:
      command: ["/bin/sh", "-c", "nginx -s quit; while killall -0 nginx; do sleep 1; done"]
```

#### Pod终止流程

当删除Pod时，K8s执行以下步骤：

1. **接收删除请求**：API Server将Pod状态标记为Terminating
2. **执行PreStop钩子**：如果定义了PreStop，先执行它
3. **发送SIGTERM信号**：kubelet向容器发送SIGTERM
4. **等待优雅终止期**：默认30秒（terminationGracePeriodSeconds）
5. **发送SIGKILL信号**：如果容器仍在运行，强制终止

```yaml
# 自定义优雅终止时间
spec:
  terminationGracePeriodSeconds: 60
```

#### 实战：完整的Pod生命周期配置

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: lifecycle-complete-demo
spec:
  terminationGracePeriodSeconds: 30
  containers:
  - name: app
    image: nginx:1.21
    ports:
    - containerPort: 80
    # 存活探针
    livenessProbe:
      httpGet:
        path: /
        port: 80
      initialDelaySeconds: 10
      periodSeconds: 5
    # 就绪探针
    readinessProbe:
      httpGet:
        path: /
        port: 80
      initialDelaySeconds: 5
      periodSeconds: 3
    # 生命周期钩子
    lifecycle:
      postStart:
        exec:
          command: ["/bin/sh", "-c", "echo 'Pod started' >> /var/log/lifecycle.log"]
      preStop:
        exec:
          command: ["/bin/sh", "-c", "nginx -s quit && sleep 5"]
    # 资源限制
    resources:
      requests:
        memory: "64Mi"
        cpu: "100m"
      limits:
        memory: "128Mi"
        cpu: "200m"
```

#### 调试技巧

当Pod出现问题时，可以使用以下命令调试：

```shell
# 查看Pod状态
$ kubectl describe pod <pod-name>

# 查看Pod日志
$ kubectl logs <pod-name>

# 查看之前容器的日志（如果容器重启过）
$ kubectl logs <pod-name> --previous

# 进入容器调试
$ kubectl exec -it <pod-name> -- /bin/sh
```

#### 总结

1. **理解生命周期**：掌握Pod从Pending到Running再到终止的完整流程
2. **合理配置探针**：根据应用特点配置合适的存活、就绪和启动探针
3. **优雅终止**：使用PreStop钩子和合理的terminationGracePeriodSeconds确保应用优雅关闭
4. **资源管理**：合理配置requests和limits，避免资源争抢
