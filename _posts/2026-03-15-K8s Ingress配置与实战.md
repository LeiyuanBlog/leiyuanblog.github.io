## K8s Ingress配置与实战

#### 前文回顾

1. 在之前的文章中,我们已经学习了Pod、Service、ConfigMap、Secret以及Deployment等核心资源--都是集群内部的基础设施。
2. 但有一个关键问题,**外部用户如何访问集群内的服务**？虽然NodePort和LoadBalancer类型的Service可以实现,但在多服务场景下管理起来并不优雅。
3. 今天我们来学习Ingress这个资源,它提供了统一的HTTP/HTTPS入口管理方案。

#### Ingress是什么

Ingress是Kubernetes中管理集群外部访问的API资源,主要提供以下能力:

- **基于域名的路由**:将不同域名的请求转发到不同Service
- **基于路径的路由**:将同一域名下不同路径的请求转发到不同Service
- **TLS/SSL终结**:统一管理HTTPS证书
- **负载均衡**:在Service层之上提供额外的负载均衡能力

##### Ingress vs Service对比

| 特性 | NodePort | LoadBalancer | Ingress |
|------|----------|-------------|---------|
| 七层路由 | ❌ | ❌ | ✅ |
| 域名支持 | ❌ | ❌ | ✅ |
| SSL终结 | ❌ | 取决于云商 | ✅ |
| 多服务复用端口 | ❌ | ❌ | ✅ |
| 成本 | 低 | 高(每个Service一个LB) | 低(一个入口) |

#### Ingress Controller

**重要概念**:Ingress资源本身只是一份规则声明,真正执行流量转发的是**Ingress Controller**。常见的Controller有:

- **Nginx Ingress Controller**(最常用)
- Traefik
- HAProxy Ingress
- Kong Ingress

##### 安装Nginx Ingress Controller

```bash
# 使用Helm安装(推荐)
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo update
helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace

# 或使用YAML安装
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.9.0/deploy/static/provider/cloud/deploy.yaml

# 验证安装
kubectl get pods -n ingress-nginx
kubectl get svc -n ingress-nginx
```

#### 基于域名的路由

最常见的使用场景--不同域名转发到不同服务:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: multi-domain-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: app-service
            port:
              number: 80
  - host: api.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: api-service
            port:
              number: 8080
```

这样,访问`app.example.com`会转发到`app-service`,访问`api.example.com`会转发到`api-service`。

#### 基于路径的路由

同一域名下,不同路径转发到不同服务:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: path-based-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /$2
spec:
  ingressClassName: nginx
  rules:
  - host: www.example.com
    http:
      paths:
      - path: /api(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: api-service
            port:
              number: 8080
      - path: /admin(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: admin-service
            port:
              number: 80
      - path: /
        pathType: Prefix
        backend:
          service:
            name: frontend-service
            port:
              number: 80
```

**pathType说明**:
- **Prefix**:前缀匹配,`/api`会匹配`/api`、`/api/`、`/api/xxx`
- **Exact**:精确匹配,只匹配完全一致的路径
- **ImplementationSpecific**:由Ingress Controller自行决定匹配规则

#### 配置TLS/HTTPS

##### 第一步:创建TLS Secret

```bash
# 使用已有证书
kubectl create secret tls example-tls \
  --cert=tls.crt \
  --key=tls.key

# 或使用YAML
```

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: example-tls
type: kubernetes.io/tls
data:
  tls.crt: <base64编码的证书>
  tls.key: <base64编码的私钥>
```

##### 第二步:在Ingress中引用

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: tls-ingress
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - app.example.com
    secretName: example-tls
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: app-service
            port:
              number: 80
```

##### 使用cert-manager自动管理证书

在生产环境中,推荐使用cert-manager配合Let's Encrypt自动签发和续期证书:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: auto-tls-ingress
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - app.example.com
    secretName: app-example-tls
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: app-service
            port:
              number: 80
```

cert-manager会自动向Let's Encrypt申请证书并存入指定的Secret中。

#### 常用Annotations配置

Nginx Ingress Controller通过annotations提供了丰富的配置能力:

##### 重写与重定向

```yaml
annotations:
  # URL重写
  nginx.ingress.kubernetes.io/rewrite-target: /
  # 强制HTTPS重定向
  nginx.ingress.kubernetes.io/ssl-redirect: "true"
  # 自定义重定向
  nginx.ingress.kubernetes.io/permanent-redirect: "https://new.example.com"
```

##### 限流与超时

```yaml
annotations:
  # 限流:每秒请求数
  nginx.ingress.kubernetes.io/limit-rps: "10"
  # 限流:并发连接数
  nginx.ingress.kubernetes.io/limit-connections: "5"
  # 代理超时设置
  nginx.ingress.kubernetes.io/proxy-connect-timeout: "60"
  nginx.ingress.kubernetes.io/proxy-read-timeout: "120"
  nginx.ingress.kubernetes.io/proxy-send-timeout: "120"
```

##### 请求体与缓冲

```yaml
annotations:
  # 最大请求体(文件上传场景)
  nginx.ingress.kubernetes.io/proxy-body-size: "50m"
  # 启用缓冲
  nginx.ingress.kubernetes.io/proxy-buffering: "on"
```

##### CORS跨域配置

```yaml
annotations:
  nginx.ingress.kubernetes.io/enable-cors: "true"
  nginx.ingress.kubernetes.io/cors-allow-origin: "https://frontend.example.com"
  nginx.ingress.kubernetes.io/cors-allow-methods: "GET, POST, PUT, DELETE, OPTIONS"
  nginx.ingress.kubernetes.io/cors-allow-headers: "Content-Type, Authorization"
```

#### 实战操作:完整部署流程

##### 第一步:准备后端服务

```yaml
# backend-apps.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend
spec:
  replicas: 2
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: frontend-svc
spec:
  selector:
    app: frontend
  ports:
  - port: 80
    targetPort: 80
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api-server
spec:
  replicas: 2
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      containers:
      - name: api
        image: hashicorp/http-echo
        args:
        - "-text=Hello from API"
        ports:
        - containerPort: 5678
---
apiVersion: v1
kind: Service
metadata:
  name: api-svc
spec:
  selector:
    app: api
  ports:
  - port: 8080
    targetPort: 5678
```

##### 第二步:创建Ingress规则

```yaml
# ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: demo-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /$2
    nginx.ingress.kubernetes.io/ssl-redirect: "false"
    nginx.ingress.kubernetes.io/proxy-body-size: "10m"
spec:
  ingressClassName: nginx
  rules:
  - host: demo.local
    http:
      paths:
      - path: /api(/|$)(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: api-svc
            port:
              number: 8080
      - path: /(.*)
        pathType: ImplementationSpecific
        backend:
          service:
            name: frontend-svc
            port:
              number: 80
```

##### 第三步:部署并验证

```bash
# 部署后端服务
kubectl apply -f backend-apps.yaml

# 部署Ingress
kubectl apply -f ingress.yaml

# 查看Ingress状态
kubectl get ingress demo-ingress

# 查看详细信息
kubectl describe ingress demo-ingress

# 获取Ingress Controller的外部IP
kubectl get svc -n ingress-nginx
```

#### 排查常见问题

##### 1. 503 Service Unavailable

```bash
# 检查后端Service和Endpoint是否正常
kubectl get svc
kubectl get endpoints

# 检查Pod是否Running
kubectl get pods

# 查看Ingress Controller日志
kubectl logs -n ingress-nginx -l app.kubernetes.io/name=ingress-nginx
```

##### 2. 404 Not Found

```bash
# 确认Ingress规则是否正确
kubectl describe ingress <name>

# 确认host是否匹配
# 确认pathType和path是否正确
```

##### 3. 证书相关问题

```bash
# 检查Secret是否存在
kubectl get secret <tls-secret-name>

# 查看证书详情
kubectl describe secret <tls-secret-name>

# 检查cert-manager日志(如使用)
kubectl logs -n cert-manager -l app=cert-manager
```

#### 生产环境最佳实践

1. **始终使用ingressClassName**:明确指定Ingress Controller,避免多Controller环境下的歧义。
2. **配置合理的限流**:防止单个客户端耗尽后端资源,使用`limit-rps`和`limit-connections`。
3. **启用HTTPS并强制跳转**:生产环境必须使用TLS,配合cert-manager实现自动化证书管理。
4. **设置合理的超时时间**:根据后端服务响应时间调整proxy超时,避免长时间挂起。
5. **配置默认后端**:为未匹配的请求提供友好的错误页面。
6. **监控Ingress Controller**:关注连接数、错误率、延迟等指标,配合Prometheus+Grafana。
7. **使用HPA扩展Ingress Controller**:在高流量场景下自动扩缩Controller Pod数量。
