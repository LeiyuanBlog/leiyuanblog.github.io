## K8s 网络策略与安全详解

#### 为什么需要网络策略

1. 默认情况下，Kubernetes集群中**所有Pod之间网络互通**，任何Pod都可以访问任何其他Pod
2. 在生产环境中，这种"完全开放"的网络模型存在严重的**安全隐患**——一旦某个Pod被攻破，攻击者可以横向移动到整个集群
3. **NetworkPolicy**是Kubernetes提供的Pod级别网络访问控制机制，类似于传统网络中的防火墙规则
4. 通过NetworkPolicy，我们可以精确控制**哪些Pod可以通信、通过哪些端口通信**

#### 核心概念

| 概念 | 说明 |
|------|------|
| Ingress规则 | 控制**入站流量**——谁可以访问目标Pod |
| Egress规则 | 控制**出站流量**——目标Pod可以访问谁 |
| podSelector | 通过标签选择策略应用的**目标Pod** |
| namespaceSelector | 选择**允许的命名空间**中的Pod |
| ipBlock | 基于**IP CIDR**范围的访问控制 |

**重要前提**：NetworkPolicy需要**网络插件支持**，常见支持的CNI插件包括Calico、Cilium、Weave Net等。注意：Flannel**不支持**NetworkPolicy。

### 一、NetworkPolicy基础

#### 1. 最简单的网络策略——拒绝所有入站流量

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-ingress
  namespace: production
spec:
  podSelector: {}          # 选择该命名空间下所有Pod
  policyTypes:
  - Ingress                # 只声明Ingress但不写规则，表示拒绝所有入站
```

**说明**：
- `podSelector: {}` 匹配命名空间下的所有Pod
- 声明了`Ingress`策略类型但没有提供任何ingress规则，等同于**拒绝所有入站流量**
- 这是"默认拒绝"安全模型的起点

```bash
# 应用策略
kubectl apply -f deny-all-ingress.yaml

# 验证：从其他Pod尝试访问
kubectl run test --image=busybox:1.36 --rm -it -- wget -qO- --timeout=3 http://target-service
# wget: download timed out  ← 流量被阻止
```

#### 2. 允许特定Pod访问

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-backend
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: backend              # 策略应用于backend Pod
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend         # 只允许frontend Pod访问
    ports:
    - protocol: TCP
      port: 8080                # 只允许访问8080端口
```

**核心逻辑**：只有带`app: frontend`标签的Pod才能通过TCP 8080端口访问`app: backend`的Pod。

#### 3. 策略叠加规则

NetworkPolicy是**叠加生效**的：
- 如果没有任何NetworkPolicy选中某Pod，该Pod的流量不受限制
- 一旦**任意一条**NetworkPolicy选中了某Pod，未被明确允许的流量就会被**拒绝**
- 多条策略的允许规则取**并集**

```
无策略:     所有流量放行（默认行为）
有策略:     只有被策略明确允许的流量才放行
多条策略:   允许规则合并，取并集
```

### 二、Ingress策略详解

#### 1. 基于命名空间的访问控制

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-from-monitoring
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: api-server
  policyTypes:
  - Ingress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: monitoring       # 允许monitoring命名空间的Pod访问
    ports:
    - protocol: TCP
      port: 9090
```

**注意**：需要先给命名空间打上标签：
```bash
kubectl label namespace monitoring name=monitoring
```

#### 2. 基于IP范围的访问控制

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-external-traffic
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: web
  policyTypes:
  - Ingress
  ingress:
  - from:
    - ipBlock:
        cidr: 10.0.0.0/8          # 允许内网IP段
        except:
        - 10.0.1.0/24             # 但排除特定子网
    ports:
    - protocol: TCP
      port: 443
```

#### 3. 组合选择器——AND与OR逻辑

```yaml
# OR逻辑：from数组中的每个元素是OR关系
ingress:
- from:
  - podSelector:                   # 条件1
      matchLabels:
        app: frontend
  - namespaceSelector:             # 条件2（OR关系）
      matchLabels:
        name: monitoring

# AND逻辑：同一个from元素中的多个选择器是AND关系
ingress:
- from:
  - podSelector:                   # 条件1
      matchLabels:                 #   AND
        app: prometheus            #
    namespaceSelector:             # 条件2
      matchLabels:
        name: monitoring
```

**关键区别**：
- 两个`-`开头的元素（数组中两个对象）：**OR**关系——满足任一条件即放行
- 同一个`-`下的多个选择器（一个对象中两个字段）：**AND**关系——必须同时满足

> ⚠️ 这是NetworkPolicy中**最容易出错**的地方，YAML缩进决定了是AND还是OR！

### 三、Egress策略详解

#### 1. 限制Pod的出站流量

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: restrict-egress
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
  - Egress
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: database           # 只允许访问database Pod
    ports:
    - protocol: TCP
      port: 5432                  # PostgreSQL端口
  - to:                           # 允许DNS解析（重要！）
    - namespaceSelector: {}
    ports:
    - protocol: UDP
      port: 53
    - protocol: TCP
      port: 53
```

**重要提醒**：限制Egress时**务必放行DNS（端口53）**，否则Pod将无法解析Service域名，导致所有基于域名的访问失败。

#### 2. 拒绝所有出站流量

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-egress
  namespace: production
spec:
  podSelector: {}
  policyTypes:
  - Egress
  # 不写egress规则 = 拒绝所有出站
```

#### 3. 只允许访问外部特定IP

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-external-api
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: payment-service
  policyTypes:
  - Egress
  egress:
  - to:
    - ipBlock:
        cidr: 203.0.113.50/32    # 只允许访问支付网关IP
    ports:
    - protocol: TCP
      port: 443
  - to:                           # DNS
    - namespaceSelector: {}
    ports:
    - protocol: UDP
      port: 53
```

### 四、实战场景

#### 场景1：三层应用的完整网络隔离

```yaml
# 1. 默认拒绝所有流量
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: production
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
---
# 2. Frontend：允许外部访问，允许访问Backend
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: frontend-policy
  namespace: production
spec:
  podSelector:
    matchLabels:
      tier: frontend
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from: []                      # 允许所有入站（通过Ingress Controller进入）
    ports:
    - protocol: TCP
      port: 80
  egress:
  - to:
    - podSelector:
        matchLabels:
          tier: backend
    ports:
    - protocol: TCP
      port: 8080
  - to:
    - namespaceSelector: {}
    ports:
    - protocol: UDP
      port: 53
---
# 3. Backend：只允许Frontend访问，只能访问Database
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: backend-policy
  namespace: production
spec:
  podSelector:
    matchLabels:
      tier: backend
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          tier: frontend
    ports:
    - protocol: TCP
      port: 8080
  egress:
  - to:
    - podSelector:
        matchLabels:
          tier: database
    ports:
    - protocol: TCP
      port: 5432
  - to:
    - namespaceSelector: {}
    ports:
    - protocol: UDP
      port: 53
---
# 4. Database：只允许Backend访问，不允许任何出站
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: database-policy
  namespace: production
spec:
  podSelector:
    matchLabels:
      tier: database
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          tier: backend
    ports:
    - protocol: TCP
      port: 5432
  egress:
  - to:
    - namespaceSelector: {}
    ports:
    - protocol: UDP
      port: 53
```

**流量拓扑**：
```
外部用户 → Frontend(:80) → Backend(:8080) → Database(:5432)
    ✅           ✅              ✅              ❌ (无外部出站)
```

#### 场景2：多租户命名空间隔离

```yaml
# 每个租户命名空间应用此策略
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: tenant-isolation
  namespace: tenant-a             # 对每个租户命名空间都部署一份
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector: {}             # 只允许同命名空间内的Pod互相访问
  egress:
  - to:
    - podSelector: {}             # 只允许访问同命名空间的Pod
  - to:
    - namespaceSelector:
        matchLabels:
          name: kube-system       # 允许访问kube-system（DNS等）
    ports:
    - protocol: UDP
      port: 53
    - protocol: TCP
      port: 53
```

#### 场景3：允许Prometheus抓取指标

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-prometheus-scrape
  namespace: production
spec:
  podSelector:
    matchLabels:
      monitoring: "true"          # 打了此标签的Pod允许被抓取
  policyTypes:
  - Ingress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: monitoring
      podSelector:
        matchLabels:
          app: prometheus
    ports:
    - protocol: TCP
      port: 9090
    - protocol: TCP
      port: 8080
```

```bash

kubectl exec -n production deploy/frontend -- \
  wget -qO- --timeout=3 http://backend:8080/health
# 200 OK ← 应该成功

# 从其他Pod测试连接backend
kubectl run test --image=busybox:1.36 -n production --rm -it -- \
  wget -qO- --timeout=3 http://backend:8080/health
# wget: download timed out ← 应该被阻止
```

#### 3. 常见排查思路

```bash
# 1. 确认CNI插件是否支持NetworkPolicy
kubectl get pods -n kube-system | grep -E "calico|cilium|weave"

# 2. 确认Pod标签是否正确
kubectl get pods -n production --show-labels

# 3. 确认命名空间标签
kubectl get namespaces --show-labels

# 4. 查看Calico的策略状态（如果用Calico）
kubectl get networkpolicies.crd.projectcalico.org -A

# 5. 抓包排查（在目标Pod中）
kubectl exec -n production deploy/backend -- tcpdump -i eth0 port 8080
```

### 六、安全加固最佳实践

#### 1. 始终从"默认拒绝"开始

```yaml
# 每个命名空间都应该有这条策略
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
```

然后逐步添加允许规则，实现**最小权限原则**。

#### 2. 不要忘记DNS

限制Egress时，**必须允许DNS流量**，否则所有基于Service名称的访问都会失败：

```yaml
egress:
- to:
    - namespaceSelector: {}
  ports:
    - protocol: UDP
      port: 53
    - protocol: TCP
      port: 53
```

#### 3. 标签管理规范

```bash
# 建议的标签体系
app: nginx                # 应用名
tier: frontend            # 层级：frontend/backend/database
env: production           # 环境
team: platform            # 团队
monitoring: "true"        # 是否允许监控抓取
```

#### 4. 策略即代码

- 将NetworkPolicy YAML纳入**Git版本管理**
- 使用CI/CD管道自动部署策略
- 变更策略前在staging环境验证
- 使用**OPA/Gatekeeper**强制要求每个命名空间必须有默认拒绝策略

#### 5. 配合其他安全机制

| 安全层级 | 机制 | 作用 |
|----------|------|------|
| 网络层 | NetworkPolicy | Pod间流量控制 |
| 认证层 | ServiceAccount + RBAC | API访问控制 |
| 传输层 | mTLS (Istio/Linkerd) | 加密Pod间通信 |
| 应用层 | PodSecurityStandard | 限制Pod权限 |
| 镜像层 | 镜像签名 + 扫描 | 防止恶意镜像 |

### 总结速查

| 场景 | 做法 |
|------|------|
| 拒绝所有入站 | `podSelector: {}` + `policyTypes: [Ingress]` 不写规则 |
| 拒绝所有出站 | `podSelector: {}` + `policyTypes: [Egress]` 不写规则 |
| 允许特定Pod | `ingress.from.podSelector` 按标签匹配 |
| 允许特定命名空间 | `ingress.from.namespaceSelector` + 命名空间标签 |
| 允许特定IP段 | `ingress.from.ipBlock.cidr` |
| AND逻辑 | 同一个from元素下放多个selector |
| OR逻辑 | from数组中放多个元素 |
| Egress别忘DNS | 放行UDP/TCP 53端口 |

NetworkPolicy是Kubernetes安全体系中**最基础也最重要**的一环。从"默认拒绝"出发，按需开放，配合RBAC、mTLS等机制，构建纵深防御体系，才能真正保障集群安全。记住：**安全不是一个功能，而是一种习惯。**
